Problem, objectives and scope

Problem

A driver needs a reachable parking space, but a sensor reading is imperfect. Choosing the first nearby space can lead to an occupied bay, while a route that ignores blocked cells is unusable. This project models these two sources of difficulty in a small parking area.

Objectives

Estimate occupancy from noisy readings, calculate a shortest legal path, and choose whether to drive, obtain another reading, skip a candidate or leave. Explain the result in the interface and make the calculations reproducible.

Scope

The application is a browser-based educational simulation of a 5 by 5 grid with three parking spaces. It does not collect live sensor data, reserve a space, detect vehicles with a camera or control a real car. Its practical value is demonstrating an explainable decision process; no real-world time or fuel savings have been measured.

Course alignment

Week 2: uninformed search, implemented as BFS. Week 6: conditional probability and Bayes rule, implemented as an occupancy update. Week 5: Markov decision processes, implemented as finite-state Value Iteration. These are separate AI topics from the supplied course schedule.

System architecture and breadth-first search

Data flow

Simulated readings and an occupancy prior enter the Bayesian update. The resulting beliefs determine which spaces count as blocked. BFS finds candidate paths and distances. The MDP uses those distances and beliefs to select an action. A recheck produces a new belief and triggers replanning.

Implementation

index.html contains the interface. js/core.js contains pure algorithms: occupancy(), bfs(), solveMDP() and plan(). js/app.js handles controls, map editing, the route preview and JSON export. tests/run.js exercises the same core module used by the application. There are no runtime package dependencies or API keys.

Search formulation

Each traversable grid cell is a state. Actions move one cell up, down, left or right. Every move has equal cost. A FIFO queue expands cells in increasing distance from the start. A visited map stores each predecessor, which reconstructs the path. BFS runs in O(V + E) time and O(V) memory.

Safety and edge cases

Roadblocks are never traversable. Other parking spaces with estimated occupancy of 50% or greater are blocked. A candidate with occupancy at or above 50% cannot be selected for driving. The candidate itself may be considered geometrically reachable for a hypothetical recheck, but a route is shown only after a Drive decision. Invalid targets, blocked targets and an enclosed start return no path.

Example

With an alert at A and no alerts at B or C, A is avoided and B is reachable in six moves. The path starts at (0,0) and ends at (2,4). All coordinates in the code are zero-based; the interface labels rows and columns from one.

Bayesian occupancy inference

Model

Let O mean occupied and A mean an alert. The prior is P(O)=0.40 by default. Sensor sensitivity is P(A|O)=0.90 and the false-positive rate is P(A|not O)=0.20. These are assumed teaching parameters, not measured device specifications.

Update equation

P(O|A) = P(A|O) P(O) / [P(A|O) P(O) + P(A|not O) (1-P(O))]. For no alert, use likelihoods 0.10 and 0.80. The user can adjust the prior from 5% to 95%.

Worked calculation

An alert gives 0.90 x 0.40 / (0.90 x 0.40 + 0.20 x 0.60) = 0.75. No alert gives 0.10 x 0.40 / (0.10 x 0.40 + 0.80 x 0.60) = 0.076923. Thus the default estimates are 75.0% and 7.7%.

Sequential reading

If the current estimate is 0.75, another alert gives 27/29 = 93.1%, while a clear reading gives 3/11 = 27.3%. The second reading uses the previous posterior as its prior. A new initial-reading scenario resets all recheck budgets.

Assumptions

Occupancy stays fixed during the two readings, and sensor errors are conditionally independent given occupancy. Correlated errors or moving cars would invalidate the simple repeated update. The application reports uncertainty rather than claiming that no alert guarantees a free space.

Finite belief-state MDP and Value Iteration

State and actions

A planning state is (i,b,k): candidate i in A/B/C, occupancy belief b in {0,...,100}/100, and recheck budget k in {0,1}. This gives 606 nonterminal states plus a terminal outcome with value zero. Each new candidate starts with its observed belief and one possible recheck. Candidate order is fixed. The actions are Drive, Check, Skip and Exit.

Transitions

Drive succeeds with probability 1-b and ends the episode. Failure has probability b and advances to the next candidate. Skip advances deterministically. Check costs one unit and yields an alert with probability 0.90b+0.20(1-b), or no alert otherwise; Bayes updates b, rounding to the nearest 1%, and consumes the recheck. Exit ends the episode. At the last candidate, advancing reaches the terminal state.

Rewards and constraints

A successful parking outcome earns +30. Failure earns -20. Driving costs 0.5 per grid step. Check costs 1 and Skip costs 0.5. Exit earns 0. Drive is unavailable for b >= 0.5 or an unreachable candidate. Check is unavailable without budget or a geometric route. Discount gamma=0.95. Rewards encode illustrative preferences, not money or measured utility.

Bellman update

V_new(s) = max_a sum_sprime P(sprime|s,a) [R(s,a,sprime) + 0.95 V(sprime)]. Values begin at zero. Synchronous sweeps continue until the maximum change is <= 1e-9, with a cap of 1000 iterations. The interface shows iterations, residual and each available action value. A greedy policy selects the largest value, using deterministic ties.

Model limits

The underlying occupancy is hidden, so this is a finite approximation of a belief-state planning problem, not an exact continuous-belief POMDP solver. Distances are computed from the entrance for each attempt; the model abstracts away the vehicle location after a failed attempt. Rechecks can change route availability when the app replans, while a single solver run keeps its distance snapshot fixed. The policy is optimal for its specified approximate model, not for every real parking situation.

Testing and results

Reproducible command

Run node tests/run.js from the repository root. The script requires Node.js and no extra packages. It writes docs/test-results.json. The browser uses exactly the same algorithm module.

Observed results

20 of 20 automated tests passed. They include analytical Bayesian posteriors, invalid inputs, unreachable targets, simple MDP solutions, all 606 Bellman states at convergence, all eight default signal combinations, and recheck outcomes. A parameter sweep checks 152 prior/signal scenarios for unsafe paths. BFS matches an independent repeated-relaxation distance oracle in 300 comparisons across 100 seeded random maps.

Original scenario

A alert, B clear, C clear: Drive to B, six moves. All clear: Drive to A, four moves. Only C clear: Drive to C, eight moves. All alerts: Check A first, without drawing a driving route. If that recheck is clear, the belief becomes 27.3% and the route to A has four moves. If repeated rechecks remain alerts, the planner can recommend Exit.

Interpretation

Unlike the original one-step reward comparison, the MDP values future candidate choices and the possible benefit of another observation. Unlike the original BFS, routing blocks likely occupied spaces. The tests establish behavior on the finite simulated cases, not real-world sensor accuracy.

Limitations of evaluation

The data are synthetic and the map is small. There is no field trial, calibrated sensor dataset or learned policy. A real deployment would need sensor calibration, dynamic obstacles, vehicle-position state, a richer action model and repeated evaluation against measured parking outcomes.
